# AVRORA.EXE · exe-11

## Что нового в exe-11: они разговаривают сами
- Иногда одна из них пишет другой в общем чате, и они говорят, пока тема не кончится (4–16 реплик). Адонис может
  читать, а может вмешаться: недосказанное отменяется, дальше говорят уже с ним.
- Разговор идёт «вживую»: у каждого сообщения своё время (прочитать, подумать, набрать), над ним видно «печатает…».
  Ход можно разбить на 2–3 коротких сообщения.
- Мысль «про себя» перед каждой репликой (как в Inner Thoughts): собеседница её не видит, Адонис — по нажатию.
- Начинают со своего: находка (с поиском), вопрос, спор, случай; видят темы прошлых разговоров и отложенные «в следующий раз».
- Защита от зацикливания: право уйти `[ухожу]`, проверка на повтор, разговор, ушедший в благодарности и общие слова,
  возвращают к конкретике или заканчивают (известная беда двух моделей без человека).
- После разговора каждая пересказывает его по-своему: Геспере — в память, Авроре — в «вы с Гесперой», которое она
  видит и в личке. Копятся настроение и заметки друг о друге (`[настроение: …]`, `[о ней: …]`).
- Общий чат → шестерёнка «Без тебя»: включить/выключить, редко/обычно/часто (1/3/6 в день), показывать мысли,
  «Пусть поговорят сейчас». Тихие часы общие с Авророй.
- В досье: «О Геспере» / «Об Авроре» и «Вдвоём» (настроение, разговоры, кто начал, чем кончилось).
- Нужен relay.py **exe-16** (`/duo/talk`, `/duo/state`, папка `/opt/aurora-relay/duo/`).

# AVRORA.EXE · exe-4

## Что нового в exe-4: картинки
- Читая страницу, Аврора получает список её картинок. `[картинка: адрес]` показывает ей картинку (видит модель), `[сохранить: адрес | описание]` кладёт в её альбом (описание «из сети: …»), дальше `[фото:id]`, посты, аватар.

- `[оставить: описание]`: фото, которое прислал Адонис, уходит в её альбом («от Адониса: …»), одно фото один раз.
- Время: с каждым сообщением в чат уходит строка с датой, часом, поясом и паузами («до его сообщения было тихо 3 ч», «его последнее сообщение было 5 мин назад»). Без неё она времени не знает и не угадывает. Нужен новый relay.py.
- Экран «Часы» (Настройки → Часы): ламповые часы на вакуумных люминесцентных индикаторах, бирюзовое свечение, мигающее двоеточие, сетка стекла.
- Память: «Загрузить копию» теперь спрашивает «Добавить» или «Заменить». «Добавить» присоединяет новое из файла к имеющемуся (ядро, эпизоды, переписка, дневник), повторы по смыслу пропускает, ничего не стирает; в журнал Авроры пишется, что Адонис добавил копию. Файл может содержать только память.

В правом верхнем углу шестерёнка: по нажатию сверху вылетает панель с живыми виджетами (время, состояние, память, планы) и значками быстрых переходов (часы, память, дневник, права, все настройки). Галерея: стикеры и альбом Авроры, в том числе картинки, которые она сохранила.

- Экран загрузки: при запуске по центру по буквам набираются строки консоли (версия, ядро, память, цитатник, «процесс запущен»), под ними полоса загрузки с процентами. Тап пропускает, выключается в Настройки → Вид.

Аврора сохраняет маркером `[в цитаты: точные слова]` (сохраняется, только если слова правда были в переписке, до 3 за ответ). Ссылка `[цитата №N]` в чате показывается карточкой, ей уходит полным текстом; весь цитатник приходит ей в контексте. ## Постоянный ключ: чтобы приложение обновлялось поверх (2.1)
До сих пор сборка подписывалась временным ключом, у каждой сборки он был другой, поэтому Android не ставил новую версию поверх старой. Теперь ключ создаётся один раз и хранится в папке `signing` закрытого (Private!) репозитория.
1. Репозиторий должен быть **Private**. Ключ лежит в нём.
2. Добавь файл `.github/workflows/make-key.yml` (содержимое из `workflow/make-key.yml`), затем Actions → Make signing key → Run workflow. Один раз.
3. Замени `.github/workflows/build-exe.yml` на новый из `workflow/build-exe.yml`.
4. Дальше каждая сборка подписана одним и тем же ключом. **Первая** установка с этим ключом потребует удалить прежнее приложение (оно подписано старым временным): сначала в приложении «Сохранить копию в файл», после установки «Загрузить копию из файла». Все следующие обновления ставятся поверх без удаления.
5. Ключ нельзя терять и нельзя показывать: если репозиторий станет публичным, его могут увидеть. Скачай копию папки `signing` и храни отдельно.

Новое в этой сборке:
- **Консольный вид.** Моноширинный текст, `аврора ▸` и `адонис ▸`, строки инструментов со знаком `$`. Вверху шапка с её состоянием и причиной.

- **Сама назначает время.** `[напишу: 21:30 | тема]` или `[напишу: через 3 ч | тема]`. До 3 сразу, до 48 часов вперёд. Тихие часы и дневной лимит на это не действуют. Когда время придёт, она может передумать. Отказы с причиной она видит в списке ограничений.

- **Рука.** Консоль на отдельном сервере. Пока сервера нет, она честно говорит, что руки нет.

## 1. Сервер (Termux)

    Z=$(ls -t /storage/emulated/0/Download/aurora-exe-v4*.zip | head -1); echo "$Z"
    unzip -p "$Z" aurora-relay/relay.py > ~/relay.new; wc -c ~/relay.new
    [ -s ~/relay.new ] && scp ~/relay.new root@92.118.112.46:/opt/aurora-relay/relay.py && ssh root@92.118.112.46 "systemctl restart aurora-relay"

Старое приложение от этого не ломается: новые поля сервер включает только по запросу из консоли.

Проверки (после обновления сервера):

    unzip -p "$Z" aurora-relay/probes.py | ssh root@92.118.112.46 "python3 - exe"
    unzip -p "$Z" aurora-relay/probes.py | ssh root@92.118.112.46 "python3 - tools"

`tools` проверяет поиск, чтение страницы и что внутренние адреса закрыты. Если поиск не вышел, это может быть закрытый выход сервера к duckduckgo, а не ошибка кода: тогда пришли вывод.

## 2. Приложение

Один раз добавить сборщик:
1. GitHub → репозиторий → Add file → Create new file.
2. Имя файла: `.github/workflows/build-exe.yml`, содержимое из `workflow/build-exe.yml` (лежит в этом архиве и отдельным файлом).
3. Commit.

Каждая сборка:
1. Загрузить `aurora-exe-v4.zip` в корень репозитория (Add file → Upload files).
2. Actions → Build EXE → Run workflow. В логе первых шагов видно, какой архив взят и `versionName = "exe-2.1"`.
3. Скачать артефакт `avrora-exe`, установить. Старое приложение остаётся.
4. Внизу настроек строка «Версия exe-4».

Не запускай Unpack, пока этот архив лежит в корне. Старые архивы из корня лучше удалять.

Первый запуск: Настройки → Подключение → вставить токен (адрес сервера подставлен). Переезд памяти: в старом приложении Память → «Сохранить копию в файл», в новом Память → «Загрузить копию из файла». Переписка и память переедут, дневник и стикеры из старого приложения нет: в файле копии их нет. Из нового приложения копия уже включает дневник.

Чтобы назначенное время приходило вовремя, у приложения должна быть снята оптимизация батареи (Настройки Android → Приложения → AVRORA.EXE → Батарея → Без ограничений).

## 3. Рука (когда будешь готов)

Сервер: любой VDS с Debian/Ubuntu, подойдёт 2 vCPU / 2 ГБ / 40 ГБ. Хостер-панель Авроре не даётся никогда, только консоль.

1. На сервере Авроры (один раз): `apt-get install -y openssh-client`, затем

       unzip -p "$Z" hand/hand_connect.py | ssh root@92.118.112.46 "python3 - keygen"

   Скрипт напечатает строку `ssh-ed25519 AAAA…`.
2. На новом сервере (от root), подставив строку из шага 1:

       unzip -p "$Z" hand/setup_hand.sh | ssh root@НОВЫЙ_IP "AURORA_PUBKEY='ssh-ed25519 AAAA… aurora-hand' bash -s"

   Создаётся пользователь `aurora`: без пароля, без sudo, вход только по ключу, без туннелей, лимиты 900 МБ / 1 ядро / 150 процессов. Выход в интернет для неё закрыт; открыть: `aurora-egress open`, закрыть: `aurora-egress closed`. В конце скрипт сам проверяет клетку и при провале не даёт подключать.
3. Подключить:

       unzip -p "$Z" hand/hand_connect.py | ssh root@92.118.112.46 "python3 - link НОВЫЙ_IP"

   Скрипт сам проверит, что у `aurora` нет sudo, и только потом пропишет руку в relay.env.
4. В приложении: Настройки → Права и рука.

Что видно и чем останавливается:
- Каждая команда и её вывод видны в чате (`$ рука: …`). Журнал команд: Права и рука → «Показать последние».
- Её папка `~/work` под git: после каждой команды, которая что-то изменила, делается снимок (`git log`, `git checkout` откатят).
- Лимит 80 команд в сутки, команда живёт до 30 секунд, вывод до 6000 знаков.
- Рука работает только в ответах на твои сообщения, сама не запускается.
- Три рубильника: в приложении (отключить руку), `aurora-off` на сервере руки, выключение сервера в панели хостера. Нажатие она видит в списке ограничений.

## Что проверено и что нет

Проверено: сервер (51 тест, включая настоящий bash и защиту адресов), скрипт связки, режимы `exe` и `tools` на готовых ответах, логика приложения и хранилище (64 теста на Kotlin), типизация ViewModel/Initiative/Diary/AuroraApi на заглушках Android.

Не проверено, потому что здесь это невозможно: сборка Android целиком (экраны Compose проверит только Actions), `setup_hand.sh` на настоящем сервере, живой поиск (разбор выдачи сделан по образцу страницы), поведение модели с новыми маркерами (для этого `probes.py exe`).

Известное ограничение чтения ссылок: адрес проверяется перед запросом, но не закрепляется за запросом (теоретически возможна подмена DNS между проверкой и запросом). Рядом с relay нет сервисов с секретами на внутренних адресах, кроме самого relay на localhost, и порты ограничены 80/443/8080/8443.
